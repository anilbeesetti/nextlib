`vp9.ivf` is a synthetic 24-frame, 64×48 VP9 clip for packet retry and flush regression tests.
Generate it with:

```sh
ffmpeg -f lavfi -i "testsrc2=size=64x48:rate=24:duration=1" -c:v libvpx-vp9 -deadline realtime -cpu-used 8 -g 12 -an vp9.ivf
```

`vp9-altref.ivf` contains 72 display frames at 128×96, including six alt-ref
superframes. With frame threading and queued output, it exercises a receive
returning EAGAIN immediately after a send returned EAGAIN. Generate it in two
passes (libvpx enables alternate reference frames only in two-pass mode):

```sh
ffmpeg -f lavfi -i "testsrc2=size=128x96:rate=24:duration=3" -c:v libvpx-vp9 -deadline good -cpu-used 4 -lag-in-frames 25 -auto-alt-ref 1 -g 48 -b:v 150k -pass 1 -passlogfile /tmp/nextlib-altref -an -f null /dev/null
ffmpeg -f lavfi -i "testsrc2=size=128x96:rate=24:duration=3" -c:v libvpx-vp9 -deadline good -cpu-used 4 -lag-in-frames 25 -auto-alt-ref 1 -g 48 -b:v 150k -pass 2 -passlogfile /tmp/nextlib-altref -an vp9-altref.ivf
```

Video draining integration fixtures are generated by `python3 generate_video_fixtures.py`
from this directory (host FFmpeg with libx264, libx265, libsvtav1 required).
The script keeps generated playback files in the ignored `build/video-fixtures/`
directory at the repository root:

- `h264-{3,48}.ts`, `hevc-{3,48}.ts`, `mpeg2-{3,48}.ts`: 160×96,
  12 fps, three-frame and four-second streams with B-frames; GOP length 12.
- `av1.ivf`: twelve 160×96 frames at 12 fps.
- `vp9-multiple.ivf`: the first and second keyframes from `vp9.ivf` packed
  into one superframe. Both visible frames inherit its single timestamp, zero.

Only the assets consumed by the Java/JNI tests are checked in here:

- `*.packets`: big-endian packet count (int32), then timestamp in microseconds
  (int64), byte length (int32), and encoded bytes for each packet. TS packet PTS
  are normalized by subtracting the minimum presentation timestamp, preserving
  decode order. IVF timestamps are rescaled using the file's rational timebase.
- `*.frames`: one expected presentation timestamp and SHA-256 of packed planar
  YUV420 per decoded frame, produced by host FFmpeg/ffprobe. Padding is excluded.
  The Java integration tests compare every frame, including the final frame.

The binary packet assets avoid a demuxer dependency in decoder tests. Generated
playback files can be used separately for playback/demuxing checks. Test EOS goes
through the production `Decoder.queueInputBuffer` path, not a native-only
null-packet call. The existing `vp9.ivf` and `vp9-altref.ivf` also remain checked in
because the native and renderer tests use them directly.

Run all Java/JNI decoder and renderer tests on a task-owned device:

```sh
ANDROID_SERIAL=emulator-5590 bash media3ext/src/androidTest/run_video_decoder_test.sh
```

Run from the repository root. The runner fails on instrumentation failures even
when `am instrument` returns exit status zero. Native tests complement this suite.
